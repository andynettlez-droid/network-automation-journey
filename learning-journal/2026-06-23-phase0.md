# 2026-06-23 — Phase 0: toolchain stand-up & validation

**Goal:** prove the ContainerLab toolchain works end to end before building any automation.

**What I did:** installed Docker (29.6.0), ContainerLab (0.76.1), and Ansible (13.1.0) inside the default WSL Ubuntu 26.04 distro. Deployed the throwaway 2-node SR Linux validation topology, confirmed both nodes reach `running`, tore it down.

**Where AI helped:** detected the existing toolchain state on the machine, authored the validation topology + setup guide, and diagnosed the deploy failure from the error text.

**What I had to verify/correct:** ← the catch. First deploy ran from the repo on `/mnt/c` (Windows drive mounted in WSL). SR Linux couldn't commit its config — `config.tmp … Operation not permitted`, plus an ACL warning — because drvfs doesn't support Linux file permissions. The containers came up but the config never committed. Fix: deploy from Linux-native disk (`~/netlab/phase0`); the commit then succeeded cleanly. New standing rule: repo source on Windows, lab runtime on Linux.

**What broke / what I didn't understand:** also hit `docker exec` permission-denied until the shell picked up the `docker` group (`newgrp docker` / fresh session). And the host's Windows `docker`/`service docker` didn't exist — Docker had to be installed *inside* Ubuntu.
