Day 1 — Idempotency

Give a router’s port an address with automation — and make re-running change nothing.

★ Concepts to remember

IdempotencyDeclare the state you want. Re-running changes nothing once the device already matches — safe to run a thousand times.
Declarative > imperativeState what should be true (“this port has this address”), not step-by-step commands. That is what makes it idempotent.
Ground truthThe tool’s “success” is a claim. The device is the proof. Always verify on the device.

Glossary

InterfaceA port on a device (e.g. ethernet-1/1) — where a cable plugs in.
IP address · /30A device’s “house number” (10.0.0.1) on a tiny 2-host network.
PlaybookThe file telling Ansible what should be true. The inventory says which device.

What you’ll watch (demonstration)

  1. Boot two virtual routers from a file.
  2. Apply the address with Ansible → changed = 1 (it made the change)
  3. Run the same thing again → changed = 0 — this flip is idempotency
  4. Ask the device (show interface) → it really shows 10.0.0.1/30 (proof)
  5. Tear it down — experiments are free.
